# Инструкция для агента

Прочитай [README](README.md) перед изменением контракта хуков. Цель проекта — получить независимый вердикт Codex по актуальной версии плана в ZCode. Инструкция в чате сама по себе не гарантировала запуск. Поэтому PostToolUse инициирует ревью, а Stop повторно сверяет документы. Проверенные версии и границы гарантии указаны в README.

## Работа с пакетом

1. Для настройки разработчика выполни из клона `./install zcode`, затем `./test-live zcode`. Сообщи результат теста и напомни начать новую сессию. Если установщик обнаружил прежние хуки, сначала объясни владельцу действие `--migrate-legacy`.
2. При работе над планом читай статус из корня Git-проекта. Для `done` сверь хеш с текущим файлом; для `NEEDS_CHANGES` открой отчёт и укажи существенные замечания. После правки дождись нового вердикта. При трёх отказах или ошибке сообщи фактический исход. Мягкий Stop не заменяет вердикт.
3. Для удаления используй `./uninstall zcode`. Конфиг может содержать другие хуки, инструменты и настройки. Управляй только записями пакета и его отмеченным блоком в AGENTS.md.

## Изменение кода

- `src/setup.py` отвечает за установку и удаление. Проверь повторную установку, чужие хуки и настройки, добавленные между установкой и удалением.
- `src/review.py` содержит обработчики, воркер и парсер. Вызов ревьюера — только `codex exec -s read-only`. Финальную строку отчёта признавай вердиктом только при успешном завершении процесса. Запись в состояние принадлежит конкретному запуску; старый воркер может записать лишь собственный отчёт.
- `tests/live.py` управляет отдельным профилем, локальным источником вызовов Write и задержкой первого воркера. Тестовые команды не должны попадать в конфигурацию рабочего профиля.
- Из корня запусти `make check`. После правок установки, хуков или тестового протокола дополнительно выполни `make test-live`. При изменении поведения обнови примеры, ограничения и схему в README.
- В среде владельца действуют глобальные правила из `~/.codex/AGENTS.md`. Финал сессии: обновить WORKLOG, запустить `~/.codex/strict-mode/bin/strict-check`, затем stage и commit. Push выполняет владелец. Другому разработчику для проверки достаточно Makefile и собственного Git-процесса.
